# 模拟器演进路线

当前已实现可缩放显示、项目切换、RGB565 显存、键盘输入、帧级 SDRAM 带宽预算和 underrun 画面演示。继续复用固件的 app/game/render，通过宿主服务扩展适配器能力。

## 后续传感器与串口

当前 Demo 已接入温度、湿度、光照滑条，宿主已提供可选的传感器和触屏回调。接下来可以按项目声明范围、步长和初值，再接入实际传感器示例、异常注入和输入回放。现有终端接收 stdout/stderr，后续可增加双向虚拟串口。

## 再后续：设备模型

1. 将当前帧级带宽预算替换为按扫描行推进的显示时钟、有限 FIFO、CPU/DMA/LTDC 仲裁；提供 FIFO 水位、欠载标志与时序图。
2. 引入虚拟时钟和外设事件，提供单步、暂停和确定性回放；由适配器主动上报显存访问量，替换整帧写入估算。
3. 逐个接入 GPIO、定时器、ADC、I2C/SPI 等应用级模型。明确可验证的寄存器行为和不支持的硬件特性。
4. 若目标变为直接执行固件 ELF/机器码，再评估 CPU 指令执行引擎与板级外设集成。这与当前编译宿主适配器运行 C 代码是不同层次，需要独立验收范围。

每一阶段都先建立能重复运行的输入场景、预期输出与回归用例，再扩展下一类硬件行为。
