## 一、Flash 几何（**必须实测确认，不能照抄**）

### 1.1 任务书给的分区

```
0x08000000 – 0x0801FFFF   128 KiB   Bootloader    Sector 0–4
0x08020000 – 0x080FFFFF   896 KiB   APP           Sector 5–11
```

### 1.2 扇区数学核对（DB1M = 0，单 Bank）

| 扇区 | 起始 | 大小 | 归属 |
|---|---|---|---|
| 0–3 | 0x08000000 | 16 KB × 4 = 64 KB | Bootloader |
| 4 | 0x08010000 | 64 KB | Bootloader |
| **5–11** | **0x08020000** | **128 KB × 7 = 896 KB** | **APP** |

```
Bootloader 合计 = 64 + 64 = 128 KB  ✅
APP 合计        = 7 × 128  = 896 KB ✅
0x08020000 + 0xE0000 = 0x080FFFFF   ✅ 正好到 1 MiB 末尾
```

**结论：任务书的分区数学是对的，可以直接用。**

### 1.3 ⚠️ DB1M 必须先验证

`DB1M = 1`（双 Bank）时扇区表**完全不同**：

| | DB1M=0（单 Bank）| DB1M=1（双 Bank）|
|---|---|---|
| 扇区 0–3 | 16 KB | 16 KB |
| 扇区 4 | **64 KB** | **16 KB** |
| 扇区 5–11 | **128 KB** | **16 KB** |
| 扇区 12–23 | — | 16 KB（Bank 2）|

**照抄单 Bank 的扇区表去擦双 Bank 芯片 → 擦错区 → 可能连 Bootloader 一起擦掉。**

**验证步骤**（上板前必做）：

```
STM32CubeProgrammer 连接 → 读：
  ① 芯片型号与 Flash 容量（应为 1 MiB）
  ② Option Bytes → DB1M 位
  ③ 读出扇区表，和上面的表逐项对
```

## 二、启动流程

```
                         ┌──────────────┐
        上电 / 复位 ─────►│  Bootloader  │
                         │  0x08000000  │
                         └──────┬───────┘
                                │
                     ┌──────────▼──────────┐
                     │ ① 读维护键（GPIO）   │
                     │ ② 读 APP 请求标志    │
                     │ ③ 读 OTA 状态记录    │
                     └──────────┬──────────┘
                                │
          ┌─────────────────────┼─────────────────────┐
          │                     │                     │
    需要维护              不需要维护              需要装 OTA
          │                     │                     │
          ▼                     ▼                     ▼
   ┌────────────┐      ┌─────────────────┐    ┌──────────────┐
   │ 串口升级模式│      │ APP 有效性判断   │    │ 校验暂存镜像 │
   │ 等 YMODEM  │      │  MSP / 入口 /   │    │ 安装到 APP 区│
   └────────────┘      │  镜像 CRC       │    └──────┬───────┘
                       └────────┬────────┘           │
                        ┌───────┴────────┐           │
                        │                │           │
                     有效             无效         成功后
                        │                │           │
                        ▼                ▼           ▼
                  ┌──────────┐   ┌────────────┐ ┌──────────┐
                  │ 跳转 APP │   │ 停在 Loader │ │ 跳转新APP│
                  └──────────┘   │ 等升级      │ └──────────┘
                                 └────────────┘
```

### 进入 Bootloader 的三种路径（P0-03 要求至少两种）

| 路径 | 实现 |
|---|---|
| **上电维护键** | 启动时读 GPIO，按下则进维护模式 |
| **APP 软件请求** | APP 写一个"请求标志"到备份寄存器/Flash 保留区，然后软复位 |
| **无有效 APP** | 自动停在 Loader（**兜底，必须有**）|

## 四、APP 侧必须改的两处

### ① 链接地址

Keil → Target → IROM1：

```
Start: 0x08020000      Size: 0xE0000      (896 KB)
```

### ② 向量表偏移

`main()` 里第一件事（在 `HAL_Init()` 之前）：

```c
SCB->VTOR = 0x08020000;
```

或者用 `system_stm32f4xx.c` 里的 `VECT_TAB_OFFSET`：

```c
#define VECT_TAB_OFFSET   0x20000
```

> **漏了这一条的症状**：APP 能跑起来，但**所有中断都跳到 Bootloader 的向量表里**，
> 表现为"串口收不到数据 / 定时器中断进不去"，而且调试器看着一切正常。

## 五、固件包格式（Manifest v1，32 字节，小端）

| 偏移 | 长度 | 字段 | 说明 |
|---|---|---|---|
| 0 | 4 | `magic` | `"FOTA"` |
| 4 | 2 | `format_ver` | 1 |
| 6 | 2 | `header_len` | 32 |
| 8 | 4 | `board_id` | F429 挑战者 V2 = `0x00004292` |
| 12 | 4 | `firmware_ver` | major<<24 \| minor<<16 \| build |
| 16 | 4 | `image_len` | BIN 有效字节数 |
| 20 | 4 | `image_crc32` | 只覆盖 `image_len` 那部分 |
| 24 | 4 | `flags` | bit0 = 强制升级 |
| 28 | 4 | `header_crc32` | 只覆盖前 28 字节 |

**两个 CRC 的范围**：`header_crc32` 不含自己；`image_crc32` 不含清单/填充/网络头。

**CRC32 参数**：IEEE reflected / zlib 兼容（poly `0xEDB88320`，init `0xFFFFFFFF`，xorout `0xFFFFFFFF`）。
校验向量：`crc32("123456789") = 0xCBF43926`。

## 六、故障清单与对策

| # | 故障 | 对策 | 对应测试 |
|---|---|---|---|
| 1 | 传输中断 / 拔线 | YMODEM 超时 → NAK → 重新开始；不标完成 | T05 |
| 2 | 坏包 / 坏 CRC | NAK 让对端重发；坏包不写入 | T04 |
| 3 | 固件长度 0 或超容量 | 擦除**之前**拒绝（`App_IsRangeInApp`）| T06 |
| 4 | APP 首字 / 复位向量非法 | `App_CheckVector` 拒绝跳转，停在 Loader | T07 |
| 5 | Flash 读回校验失败 | 镜像标为无效，不跳转 | T08 |
| 6 | 跳转后中断异常 | 跳转前清外设/NVIC/VTOR/MSP | T09 |
| 7 | 重复包（ACK 丢失）| ACK 但**不重复写** | — |
| 8 | 序号乱跳 | ABORT，重进升级流程 | — |
| 9 | 断电（安装阶段）| 保留候选镜像，重新校验后安装 | T11（P1）|
| 10 | 篡改镜像 | CRC 不符 → 拒绝安装 | T12（P1）|

## 七、安全红线（任务书第 23 行）

```
✗ 不得擦除/覆盖 Bootloader 区（Sector 0–4）
✗ 不得擦除 Option Bytes
✗ 不得擦除未知分区或不属于本工程的固件区域
✗ 严禁把外部包里的地址直接当作 Flash 写地址
✗ 所有故障注入只能在 APP 和指定暂存区进行
```

**代码层面的落实**：

- 所有擦写都经 `flash_if.c`，入口第一件事就是 `App_IsRangeInApp(addr, len)` 检查
- YMODEM 的累计写入量超过 `max_size` 立刻 ABORT
- 目标地址**永远由 offset 累加得出**，绝不从包里读地址
