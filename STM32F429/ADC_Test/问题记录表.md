## 第 1 条（详细）

**问题现象**

把 I2C 作业里的 `oled.c` / `oled.h` / `bsp_oled_codetab.h` 复制到新建的 `ADC_Test` 工程后，编译报 3 个错误：

```
../Core/Src/oled.c(15): error: #20: identifier "I2C_HandleTypeDef" is undefined
../Core/Src/oled.c(26): error: #20: identifier "I2C_MEMADD_SIZE_8BIT" is undefined
../Core/Src/oled.c(38): error: #20: identifier "I2C_MEMADD_SIZE_8BIT" is undefined
```

**原因分析**

新工程在 CubeMX 里只勾了 ADC 和 USART，**没有启用 I2C**。
CubeMX 生成 `stm32f4xx_hal_conf.h` 时，只有被启用的外设才会 `#define HAL_xxx_MODULE_ENABLED`。I2C 没启用 → HAL 的 I2C 头文件没被包含 → `I2C_HandleTypeDef` 这些类型全都不存在。
`stm32f4xx_hal_i2c.c` 也没被加进 Keil 工程。

**排查过程**

1. 先看错误数量（3 个）和位置 —— **全部集中在 `oled.c`**，`main.c` 没报错。
2. 看错误内容 —— 不是语法错，是"标识符未定义"，说明缺类型定义。
3. 反推：`I2C_HandleTypeDef` 来自 `stm32f4xx_hal_i2c.h`，而它是否被包含取决于 `stm32f4xx_hal_conf.h` 里的 `HAL_I2C_MODULE_ENABLED`。
4. 结论：**不是代码问题，是工程配置漏了外设**。

**最终解决方案**

CubeMX 里补配 I2C1：
- `Connectivity → I2C1` → Mode = I2C
- Standard Mode，100 kHz
- 引脚 PB6(SCL) / PB7(SDA)
- GENERATE CODE

生成后 `stm32f4xx_hal_conf.h` 里出现 `HAL_I2C_MODULE_ENABLED`，`stm32f4xx_hal_i2c.c` 也被自动加进 Keil 工程，编译通过。

**经验**：报"某类型未定义"时，先想**那个类型属于哪个模块、那个模块有没有被使能**，而不是去改代码。

## 第 2 条（详细）

**问题现象**

查原理图的 SENSOR 页，只有 PA5 和 PC3 两个 ADC 引脚。PC3 已验证是电位器，于是推断 **PA5 是板载光敏电阻**，配置为 ADC1_IN5 读取。
但无论转电位器、用手电照、还是用鼠标垫盖住板子，**读数始终在 2000 左右小幅跳动，不随任何操作变化**。

**原因分析**

`2000` 这个值（约 1.6 V，正好是 3.3 V 的一半）是**悬空脚**的典型表现：引脚没接任何东西，处于高阻态，会被环境噪声拉到中间电平附近。

**排查过程**

1. **转电位器** → 读数不变 → 排除"PA5 是电位器"。
2. **遮光 / 照光** → 读数不变 → 排除"PA5 是光敏电阻"。
3. 结合数值（中间电平 + 小幅抖动）→ 判断为**空排针/悬空脚**。

**最终解决方案**

改用外置模拟量传感器：

| 模块引脚 | 接到 |
| --- | --- |
| VDD | 3.3 V（**不能接 5V**，否则 AO 可能超过 3.3V 烧引脚）|
| GND | GND（必须共地）|
| AO | **PB0**（ADC1_IN8）|
| DO | 不接（数字开关量，ADC 用不上）|

CubeMX 里取消 IN5、改勾 IN8，Rank2 自动变为 `ADC_CHANNEL_8`。

**经验**：判断"引脚上有没有器件"，看两点 —— **数值是不是停在中间电平**、**改变环境后动不动**。

## 第 3 条（详细）

**问题现象**

接入光敏模块后，把 ADC 原始值线性映射成 0~100 的光强百分比，结果**用光照它，百分比反而变小；遮住它，百分比变大**。

**原因分析**

这类模块的 AO 是**分压输出**：

```
VDD ──[ 光敏电阻 ]──┬── AO
                     │
                  [ 固定电阻 ]
                     │
                    GND
```

光照增强 → 光敏电阻阻值**下降** → 分压点电压**下降** → ADC 读数变小。
所以"原始值"和"光强"是**反相关**的。

**排查过程**

1. 遮光和照光各记录一组读数，确认二者反相关（不是代码算错）。
2. 排除 ADC 配置问题：原始值本身随光照连续变化，说明采样正确。

**最终解决方案**

在映射时先取反：

```c
lux = ((4095u - senRaw) * 100u) / 4095u;   /* 取反后：越亮越大 */
```

**经验**：**先确认传感器输出方向和物理量是正相关还是反相关，再写业务逻辑。**
如果直接拿原始值和阈值比较，就会出现"越亮越不报警"的诡异行为 —— 所以两路都先换算到同一把"越亮越大"的尺子（0~100）再比较。

## 第 4 条（详细）

**问题现象**

报警逻辑在阈值附近来回跳，LED 闪烁。
按常规办法加了**迟滞**（进入/解除用两个不同门槛，回差 ±2），**结果仍然闪** —— 说明抖动幅度比回差还大。

**原因分析**

两个原因叠加，但主因是**闭环正反馈**：

```
报警 → 红灯亮 → 光敏电阻被照亮 → LUX 升高 → 判断
  ↑                                              │
  └──────────── 状态翻转 ←───────────────────────┘
```

报警灯是**执行器**，光敏电阻是**传感器**，两者在同一个物理环境里 —— 执行器的动作改变了传感器的输入，形成自激振荡。
（这和音响"麦克风靠近音箱就啸叫"是同一个原理。）

此时扰动的幅度**由灯本身决定**，与 ADC 噪声无关，所以**迟滞再大也只是把振荡周期拉长，停不住**。

**排查过程**

1. 迟滞加到 ±2 无效 → 首先排除"普通噪声"这个假设。
2. 增加诊断代码：统计 `lux` 在最近 10 秒（50 次采样）内的 **min / max**，显示成 `d:min-max`。
3. 实测 `d:6-27` —— 跨度 21 格，约 **860 个 ADC 码**。而 12 位 ADC 的正常噪声只有 ±10~20 码，相差两个数量级 → **证明不是噪声，是真实的环境变化**。
4. 检查实物布局，发现**光敏模块被放在了报警 LED 旁边** → 定位到耦合路径。

**最终解决方案**

1. **物理隔离（主）**：光敏传感器远离并背对报警灯，或用遮光罩只让它"看外面"。
2. **保留迟滞（辅）**：作为第二道防线，抑制剩余的噪声抖动。
3. **可选的根治方案**：报警改用**蜂鸣器**等不发光的方式，从根本上切断光耦合。

迟滞的写法（关键是 `alarm` 必须 `static`，否则记不住上一次状态，迟滞不成立）：

```c
static uint8_t alarm = 0;                 /* 跨轮次保持 */

int32_t lo = thresh - ALARM_HYST;
int32_t hi = thresh + ALARM_HYST;

if      (lux > hi) alarm = 1;             /* 明显超过门槛 → 报警 */
else if (lux < lo) alarm = 0;             /* 明显低于门槛 → 解除 */
/* lo~hi 之间保持原状态，不抖 */
```

**经验（最重要的一条）**：

> **执行器和传感器不能互相看见。**
> 一旦执行器的输出能反过来改变传感器的读数，系统就会自激 —— 这不是软件能完全解决的，必须从**物理布局**上断开这条耦合路径。

同类问题：温度传感器贴在加热器出风口、麦克风对着音箱、电机编码器和电机电源走同一束线。
