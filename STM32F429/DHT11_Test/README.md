# DHT11_Test — 按键 + 串口双路控制的灯控与温湿度终端

> 本工程最初是 **DHT11 单总线驱动**的学习实验，现已扩展为**嵌入式技术第一阶段考核**的完整实现。
> 硬件：野火 STM32F429 开发板（板载 RGB 红灯 PH10、KEY1/KEY2、DHT11）

## 二、串口协议

**115200 / 8 位数据位 / 无校验 / 1 位停止位。**
命令以 `@` 开始、`\n` 结束（兼容 `\r\n`，**忽略其中的 `\r`**），一律使用大写字母。响应统一以 `\r\n` 结束。

| 功能 | 发送 | 响应 |
| --- | --- | --- |
| 开灯 | `@LED=1` | `OK,LED=1` |
| 关灯 | `@LED=0` | `OK,LED=0` |
| 灯状态查询 | `@LED?` | `LED=1` |
| 环境查询 | `@ENV?` | `ENV,T=26,H=58` |
| 启动闪烁 | `@BLINK=1` | `OK,BLINK=1` |
| 停止闪烁（并关灯） | `@BLINK=0` | `OK,BLINK=0` |
| 开启周期上报 | `@REPORT=1` | `OK,REPORT=1` |
| 关闭周期上报 | `@REPORT=0` | `OK,REPORT=0` |
| 非法命令 / 参数 | `@LED=3`、`@LED=1ABC` | `ERR,CMD`（**LED 不变**） |
| 超长命令（> 32 字节） | 超过 32 字节 | `ERR,LENGTH` |
| 不完整命令 | 发 `@LED=` 后 2 秒内无 `\n` | `ERR,TIMEOUT`（只报一次） |
| 无有效环境数据 | `@ENV?` | `ERR,SENSOR` |

> ⚠️ **调试提示**：串口助手的「追加**回车**」发的是 `\r`（0x0D），「追加**换行**」发的才是 `\n`（0x0A）。
> 本协议只认 `\n`，而 `\r` 是被**故意忽略**的——勾错选项会表现为「发什么都不回，2 秒后报 `ERR,TIMEOUT`」。
> 拿不准就用 HEX 发送 `40 4C 45 44 3D 31 0A`（= `@LED=1\n`）。

## 三、硬件连接 / 引脚表

| 外设或信号 | 引脚 | 配置或有效电平 |
| --- | --- | --- |
| LED | **PH10** | 推挽输出；板载 RGB **红灯**，**共阳极 → 低电平点亮** |
| KEY1 | **PA0** | 输入、内部下拉，**按下 = 高电平** |
| KEY2 | **PC13** | 输入、内部下拉，**按下 = 高电平** |
| 串口 TX / RX | **PA9 / PA10** | USART1，115200-8-N-1，**已使能全局中断** |
| DHT11 数据 | **PB0** | 运行中动态改写 `MODER` 在输出↔输入间切换，内部上拉。3.3 V 供电，**不可接 5 V** |
| 基础定时器 | **TIM6** | PSC = 8999，ARR = 99 → 90 MHz ÷ 9000 ÷ 100 = **100 Hz（10 ms）** |

> PH10 / PH11 / PH12 分别是板载 RGB 的红 / 绿 / 蓝。

## 四、实现要点

### 1. 三个时间源，分工明确

| 时间源 | 精度 | 用途 |
| --- | --- | --- |
| `g_tick10`（TIM6 中断累加） | **10 ms** | 按键扫描、接收超时、闪烁、上报周期、DHT11 采样调度 |
| `HAL_GetTick()`（SysTick） | 1 ms | HAL 内部延时 |
| `DWT->CYCCNT` | **1 µs** | DHT11 单总线时序（`HAL_Delay` 最小 1 ms，不够用）|

### 2. 中断只计数、只收字节

```c
void HAL_TIM_PeriodElapsedCallback(TIM_HandleTypeDef *htim) {
    if (htim->Instance == TIM6) g_tick10++;      /* 只做这一件事 */
}

void HAL_UART_RxCpltCallback(UART_HandleTypeDef *huart) {
    if (huart == &huart1) {
        Cmd_FeedByte(rx_byte);                   /* 只收字节、改状态机，绝不发串口 */
        HAL_UART_Receive_IT(&huart1, &rx_byte, 1);
    }
}
```

**中断接收需要两件事同时成立**：① 外设内部开中断（`HAL_UART_Receive_IT()` 干的）；② **NVIC 里使能这个中断源**（CubeMX 勾 `USART1 global interrupt`）。
少一个中断永远不来，**而且不报错**——表现为「发什么都不回」。

### 3. 串口接收状态机（逐字节）

```
【IDLE 空闲】
   └─ '@'  → 清缓冲、开始计时 → 【RECVING】
【RECVING 接收中】
   ├─ '\n'  → 置「整行就绪」标志 → 主循环解析 → 回 IDLE
   ├─ '\r'  → 忽略（也不重置计时）
   ├─ '@'  → 丢弃旧命令，以新 '@' 重新开始，计时归零
   ├─ 其他  → 存缓冲（最多 31 字符）；超了则置超长标志
   └─ 满 2 秒 → 主循环发一次 ERR,TIMEOUT → 回 IDLE
```

**为什么不用 DMA + 空闲中断？** 协议的三条规则（计时从 `@` 起算、后续字符不重新计时、接收中再遇 `@` 重开）都作用在**接收过程中**，必须逐字节知道每个字节何时到达。空闲中断只能在一帧结束后交出整块数据。

### 4. LED 状态的唯一来源

`LED_GetState()` **不存影子变量**，而是直接读 `ODR` 的 bit10（共阳极：位为 0 = 亮）。
这样**闪烁过程中查询也一定返回当时真实状态**，不存在「记的状态和实际不一致」。

### 5. LED 操作用 BSRR（原子写）

```c
LED_PORT->BSRR = (uint32_t)LED_PIN << 16;   /* 高半区 = 置低 = 点亮 */
LED_PORT->BSRR = LED_PIN;                   /* 低半区 = 置高 = 熄灭 */
```

低 16 位 = 置高（SET）= `1u << n`；高 16 位 = 置低（RESET）= `1u << (n+16)`。
BSRR 一次写完成，**不需要「读—改—写」**，所以不会覆盖掉同一端口其它位的变化。

## 六、技术笔记

### DHT11 单总线协议速记

```
【起始】主机拉低 18ms → 释放
【响应】从机：80us 低 + 80us 高
【数据】40 bit，每 bit = 50us 低 + 高电平
          高电平 26us  → 该 bit = 0
          高电平 70us  → 该 bit = 1
【内容】湿度整数 + 湿度小数 + 温度整数 + 温度小数 + 校验和
        （校验和 = 前 4 字节之和的低 8 位）
```

### 其他

- **DWT 使能三行**是"标准咒语"；`1us = 180 个 CPU 周期`（180 MHz）
- **两种时间尺度**：应用层用毫秒（`g_tick10`），协议层用微秒（DWT）
- **共阳极**：引脚拉高 → 两端没有电压差 → 灯灭。所以 `GPIO_PIN_SET` 反而是"灭灯"
- `IDR` 读电平、`MODER` 切方向、`BSRR` 拉高拉低
- 定时周期 = `(PSC+1) × (ARR+1) ÷ 定时器时钟`；**APB 预分频 ≠ 1 时，定时器时钟 = APB 时钟 × 2**
- `HAL_GetTick()` 溢出（回绕）不影响判断：只要用 `now - last` 相减，无符号数自动回绕

### 已知可改进点

1. **超时 / 闪烁 / 上报按「`Cmd_Tick10ms()` 被调用的次数」计时**，而不是用 tick 差值。
   误差约 1%（DHT11 读取会阻塞约 20 ms，吃掉几个 tick）。
   更好：收到 `@` 时记录 `g_tick10`，之后用 `g_tick10 - start >= 200` 判断（无符号相减自动回绕）。
2. **串口接收缓冲区由中断和主循环共用**。极端情况（10 ms 内连发两条命令）可能丢一条响应。
   更好：中断只往环形缓冲塞字节，接收状态机整体搬到主循环。
