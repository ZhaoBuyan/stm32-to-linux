# LED_Key_Control — RGB 三色循环 + 按键暂停

## 功能

实现三个灯珠的循环亮起，并通过按钮来控制灯珠循环的暂停与继续

## 现象

默认情况下，红、绿、蓝三个灯珠交替开启
按键之后循环停止，再次按键之后循环重新开始计时，继续循环颜色

## 遇到的问题 & 解决

1. 引脚被抢：初始化设的电平被主循环覆盖 → 一个引脚只能有一处控制
2. 按键全灯灭：Key_Scan 里的 LED_AllOff 抢了主循环 → 删掉
3. 恢复后立刻跳色：last_change 暂停期间没更新 → 暂停时刷新成当前时刻
4. 卡死：暂停分支里写了 while(1) → 改成单次判断

## 关键点

1. 为什么 GPIO_PIN_SET（引脚拉高）反而是"灭灯"？
   灯珠是共阳极的，引脚拉高的话两端就没有电压差。

2. HAL_GetTick() 溢出（回绕）了，判断还准吗？为什么？
   无符号数字相减自动回绕（就像是单向的绳圈一样），所以只要 now - last 相减，即使 tick 溢出，差值依然正确，定时判断不受影响。

3. BSRR 机制：GPIOH->BSRR 是 32 位寄存器，低 16 位对应 PH0~PH15 的"置高"，高 16 位对应"置低"。寄存器内一位如果被置为1，这个指令会强制把它所在位置对应的电平置为它所在位置指示的电平（低半区指定为"高电平"、高半区指定为"低电平"），避免了“读——改——写”的过程，简化了系统。

4. 为什么用 HAL_GetTick() 时间戳，不用 HAL_Delay()？
   HAL_Delay 会阻塞主循环，CPU状态为忙等，无法响应其他的按键、外设；用"当前时刻 − 上次时刻 ≥ 阈值"的非阻塞判断，在CPU轮到该命令时就会判断，延迟可以忽略不计，主循环一刻不停，还能同时处理灯和按键。
