## 一、功能对照（任务书 §3）

### 基础任务

| 模块 | 要求 | 实现 |
| --- | --- | --- |
| **模块 1** | 单字节写入与读取 | `EE_WriteByte()` / `EE_ReadByte()` |
| | 多字节连续写入与读取 | `EE_WriteBuf()`（**按 8 字节分页**）/ `EE_ReadBuf()` |
| | 写入数据回读校验 | `EE_SelfTest()`：16 字节跨页写→读→逐字节比对，串口打印 PASS/FAIL |
| **模块 2** | 屏幕初始化与清屏 | `OLED_Init()` / `OLED_CLS()` |
| | 指定位置 ASCII 字符、字符串 | `OLED_ShowChar()` / `OLED_ShowStr()`（支持 6x8、8x16，自动换行）|
| | 十进制数字显示 | `OLED_ShowNum()` |
| **模块 3** | 3 组参数存 EEPROM 指定地址 | `sys_param_t` + 地址 0x00~0x09 规划（见 `eeprom.h`）|
| | 上电自动读取 + 分屏显示 | `APP_Init()` → `APP_Display()`（屏上分 4 个区域）|
| | KEY_UP 计数 +1 并写回 | `APP_KeyUp()` |
| | KEY_DOWN 恢复出厂并写回 | `APP_KeyDown()` |
| | 掉电保持 | magic 字节 + 校验字节 + 每次变更立即写回 |

## 二、硬件接线

| 信号 | 引脚 | 配置 |
| --- | --- | --- |
| OLED / EEPROM SCL | **PB6** | I2C1，复用开漏 |
| OLED / EEPROM SDA | **PB7** | I2C1，复用开漏 |
| 调试串口 TX / RX | **PA9 / PA10** | USART1，115200-8-N-1 |
| KEY_UP | **PA0** | 输入、内部下拉，按下为高 |
| KEY_DOWN | **PC13** | 输入、内部下拉，按下为高 |
| 系统时钟 | 25 MHz 晶振 | HSE → PLL(25/360/2) → **180 MHz**，APB1=/4、APB2=/2 |

**从机地址**（7 位 / 8 位两种写法，HAL 要 8 位形式）：

| 器件 | 7 位 | 传给 HAL |
| --- | --- | --- |
| AT24C02（EEPROM） | 0x50 | **0xA0** |
| SSD1306（OLED） | 0x3C | **0x78** |

> AT24C02 和 OLED 共用 I2C1 一条总线 —— 这正是 I2C「多设备总线」的特点：靠不同从机地址区分。

## 三、模块结构（驱动与业务分离）

```
Core/
├── Inc/
│   ├── eeprom.h      AT24C02 接口（只暴露按字节/按块读写）
│   ├── oled.h        SSD1306 接口
│   ├── app.h         业务层接口（参数/按键/显示）
│   ├── key.h         两键消抖接口
│   └── bsp_oled_codetab.h   字库（野火提供，仅 oled.c 包含）
└── Src/
    ├── eeprom.c      I2C 细节全在这里
    ├── oled.c        命令/数据、初始化序列、字模取点
    ├── app.c         参数打包/解包、加载、保存、屏幕布局
    ├── key.c         三态机消抖
    └── main.c        CubeMX 生成 + USER CODE 里的调度
```

**分层原则**：`app.c` 里看不到任何 `HAL_` 调用，只调 `EE_xxx` / `OLED_xxx`；
换一块 EEPROM 或换一种屏，只改驱动层，业务层不动。

## 四、关键设计（答辩要点）

### 1. 为什么 I2C 地址要左移一位
I2C 线上是 8 位：**7 位地址 + 1 位读写方向**。AT24C02 数据手册写 0x50，写操作就是 `0x50<<1|0 = 0xA0`。
HAL 的 `HAL_I2C_Mem_Write` 等函数要求传**已经左移过的 8 位形式**（头文件注释：*"The device 7 bits address value in datasheet must be shifted to the left"*）。

### 2. 为什么写要分页、读不用
AT24C02 的页写指针**在页内回绕**：从 0x06 一次写 4 字节 → 落到 0x06,0x07,**0x00,0x01**，把页头覆盖掉且不报错。
所以写入必须按「本页剩余空位」切块（`EE_WriteBuf`）。
读没有这个问题：连续读时地址自动递增并回绕。

### 3. 为什么每次写完等 5 ms
`tWR`（写周期）最大 5 ms。这段时间芯片内部在烧写，**不响应 I2C**。不等就会偶发丢数据。

### 4. 为什么参数要逐字段拆字节，不能 `memcpy` 结构体
结构体有编译器填充字节，且大小端不保证。存进 EEPROM 的数据要跨版本读，必须逐字段按固定字节序打包（见 `APP_Pack`）。

### 5. SSD1306 的「控制字节」
SSD1306 没有寄存器地址概念，用控制字节区分：`0x00` = 后面是命令，`0x40` = 后面是显存数据。
所以驱动里用 `HAL_I2C_Mem_Write(..., 0x78, 0x00/0x40, ...)` 就是在发这两类字节。

## 五、参数存储布局

| 地址 | 长度 | 内容 |
| --- | --- | --- |
| 0x00 | 1 | magic = `0xA5`（判断"有没有存过"）|
| 0x01 | 2 | 设备 ID（大端）|
| 0x03 | 4 | 运行计数（大端，32 位）|
| 0x07 | 2 | 固件版本号（大端，0x0100 = v1.00）|
| 0x09 | 1 | 校验字节（前 9 字节累加和低 8 位）|
| 0x20 | 16 | `EE_SelfTest()` 自检专用区（故意跨页）|

```powershell
# 需要 mingw32-make 或 gcc 在 PATH 里
gcc -std=c11 -Wall -Wextra -O2 -o ee_test.exe sim_hal.c ee_impl.c test_main.c
.\ee_test.exe
```
