# GPS_Test —— GPS NMEA 原始数据回显

> **这一步不解析，只把收到的原始 NMEA 打到串口上。**
> 目的：确认接线、波特率、数据真实性。

对应任务书 M2.1 的第一条：

> 「先用 USB-TTL 或 MCU 串口**原样打印/记录** GPS 原始 NMEA；
> 确认数据源真实、波特率正确，再做结构化解析。」

## 一、接线

| GPS 模块 | STM32F429 | 说明 |
|---|---|---|
| **TX** | **PB11**（USART3_RX）| **必须接** —— 数据从这里进 MCU |
| **RX** | PB10（USART3_TX）| 可选。只收数据时不用接 |
| **VCC** | 3.3V 或 5V | **看模块标注**。多数模块支持 3.3~5V |
| **GND** | GND | **必须接**，共地 |

### 为什么选 USART3 / PB10-PB11

这个工程基于 `Template_LCD`，已被占用的引脚：

```
LTDC（屏）     PA3/PA11/PA12/PB0/PB1/PB8/PB9/PC0/PC7/PD0/PD1/PD6/PE0-PE15/PF0-PF5/PF10-PF15/PG0-PG2/PG4-PG8/PG10-PG12/PG15/PH2-PH8/PH10-PH13/PH15/PI0/PI2/PI4/PI8-PI10
FMC（SDRAM）   同上（与 LTDC 共用大量引脚）
USART1（调试）  PA9 / PA10        ← 不能用
I2C1（MPU）     PB6 / PB7
SPI5（Flash）   PF6 / PF7 / PF8 / PF9
触摸            PH4 / PH5（GT911）+ PI8 / PD13
按键            PA0 / PC13
LED             PH10 / PH11 / PH12
```

**PB10 / PB11 空闲**，而且不和其他外设冲突 → 用 USART3。

## 二、串口输出：自检报告（不是原始 NMEA）

默认 `RAW_ECHO = 0`，串口不再刷原始语句，而是**每 2 秒打一份自检报告**，
状态一变化（比如从"未定位"变成"已定位"）**立刻**多打一份，不用等。

```
=============== GPS SELF-TEST ===============
[01] uart      USART3 @9600                PASS
[02] data      264 lines / 0 bad-cs        PASS
[03] module    ANTENNA OPEN reported       (module text, not measured)
[04] sats      visible 0   used 0          FAIL  <-- go outdoors / near window
               (module also reports ANTENNA OPEN -- if this happens
                outdoors too, the antenna is really not connected)
[05] fix       FIX_INVALID no fix          WAIT
[06] position  none yet (never had a fix)
=============================================
```

定位成功后会多出 6~12 行：

```
[05] fix       FIX_VALID   GPS              PASS
[06] lat       31.8451022 N
[07] lon       117.1984812 E
[08] speed     22.863 km/h
[09] altitude  46 m
[10] hdop      0.9
[11] utc       08:18:36
[12] fix age   120 ms
```

### 每个字段从哪来

| 行 | 数据来源 | 谁测的 | 说明 |
|---|---|---|---|
| `[01] uart` | 波特率搜索 | **我们自己测** | 主动试 6 个波特率并验校验和 |
| `[02] data` | 语句计数 | **我们自己测** | `bad-cs` = 校验和失败的条数 |
| `[03] module` | `GPTXT` 文本 | **完全没有测** | 只是转发模块说的一句话，**不代表天线好** |
| `[04] sats` | `GSV`（可见）+ `GGA`（参与定位）| 模块测的 | **可见 ≠ 参与**，见下；天线的真正结论看这里 |
| `[05] fix` | `RMC` 状态字段 + 子状态机 | 模块 + 我们 | `PASS/WAIT/FAIL` |
| `[06][07]` | `RMC` 经纬度 | 模块测的 | 度分已转十进制度，负号表示南纬/西经 |
| `[08]` | `RMC` 第 8 段 | 模块测的 | 节 × 1.852 |
| `[09][10]` | `GGA` | 模块测的 | 海拔、HDOP |
| `[11]` | `RMC` 第 2 段 | UTC |
| `[12]` | 内部计时 | 上次有效定位距今多久，超过 3 秒标 `(STALE)` |


### 关于 `[03] module` 这一行（一个重要更正）

这一行以前叫 `[03] antenna ... PASS/FAIL`，那是**错的**：程序并没有测天线，
只是在 NMEA 文本里找 `ANTENNA OPEN` 这几个字。

- 模块报了 → 我们知道有问题
- 模块没报 → **不代表天线好**（换个不发 `GPTXT` 的模块，这里会永远显示 PASS）

所以现在去掉了 `PASS/FAIL`，只写"模块说了什么"，并标注 `(module text, not measured)`。

**天线的真正结论要看 `[04] sats`**：

| 现象 | 结论 |
|---|---|
| `visible > 0` | 天线在收信号，能用 |
| `visible = 0`，在室内 | 先换位置（窗边/室外），不能下结论 |
| `visible = 0`，在室外 | 天线确实不通 |

原则：**只汇报确实测到的东西，把没测的东西标成"没测"**，不要在自检里冒充测量。
### 「可见卫星」和「参与定位卫星」不是一回事

| | 含义 | 来自 |
|---|---|---|
| **可见**（visible）| 天线能看到几颗（能收到信号但可能不参与解算）| `GSV` 第 4 段 |
| **参与**（used）| 真正用于算出位置的几颗 | `GGA` 第 8 段 |

**可见 > 0 但参与 = 0** 是很常见的中间状态：说明天线在收信号了，
但还没凑够解算条件（星太少、几何分布差、还没收敛）。
这个阶段会有 `HDOP` 偏大（几十），耐心等 30 秒~几分钟通常会掉到 1~2。

### 想看原始 NMEA 时

把 `User/main.c` 顶部的 `RAW_ECHO` 改成 `1` 即可，其他逻辑不变。

## 三、怎么判断"通了"

**看到以 `$` 开头的行就通了。** 典型的两种：

```
$GNRMC,hhmmss.ss,A,ddmm.mmmm,N,dddmm.mmmm,E,speed,course,ddmmyy,,,A*CS
$GPGGA,hhmmss.ss,ddmm.mmmm,N,dddmm.mmmm,E,fix,sats,hdop,alt,M,...
```

### 关键字段速查（RMC）

| 位置 | 含义 | 要注意 |
|---|---|---|
| `$GNRMC` | talker=`GN`（多星座），`GP`=`GPS` | **`GN`/`GP`/`BD` 都会出现，解析要兼容** |
| 第 2 段 | UTC 时间 `hhmmss.ss` | — |
| 第 3 段 | **`A` = 有效 / `V` = 无效** | **`V` 时纬度经度全是空的，不能拿去算里程** |
| 第 4-5 段 | 纬度 `ddmm.mmmm` + `N/S` | 是**度分**，不是十进制度 |
| 第 6-7 段 | 经度 `dddmm.mmmm` + `E/W` | 同上 |
| 第 8 段 | **地面速度，单位「节」** | `km/h = 节 × 1.852` |
| 最后 `*CS` | 校验和 | `$` 和 `*` 之间所有字节异或 |

> **在室内多半是 `V`（无定位）**，或者空字段。这是正常的 ——
> 室内测的是"数据链路通不通"，不是"能不能定位"。
> 真要定位得拿到窗边或室外，等几十秒冷启动。

## 三点五、实测记录（2026-11-16，室内、天线未接好）

### 观察到的原始输出（一个周期）

```
$BDGSV,1,1,00*68
$GNRMC,,V,,,,,,,,,,N*4D
$GNVTG,,,,,,,,,N*2E
$GNZDA,,,,,,*56
$GPTXT,01,01,01,ANTENNA OPEN*25
$GNGGA,,,,,,0,00,25.5,,,,,,*64
$GNGLL,,,,,,V,N*7A
$GPGSA,A,1,,,,,,,,,,,,,25.5,25.5,25.5*02
$BDGSA,A,1,,,,,,,,,,,,,25.5,25.5,25.5*13
$GPGSV,1,1,00*79
$BDGSV,1,1,00*68      ← 开始下一轮，约 1 Hz
```

### 结论

| 检查项 | 结果 |
|---|---|
| 串口链路 | ✅ **通**。1 秒 11 条语句，连续稳定 |
| 波特率 | ✅ 自动锁定，无乱码 |
| **校验和** | ✅ **24 条全部通过，0 失败** |
| 环形缓冲 / 组行 | ✅ 无丢字节（丢一个字节校验和就会失败）|
| 定位 | ❌ **无定位**，0 颗卫星 |

**校验和全对是链路正确的最强证据** —— 只要丢一个字节，`*CS` 就对不上。

### 无定位的原因：`ANTENNA OPEN`

```
$GPTXT,01,01,01,ANTENNA OPEN*25
```

模块自己报告**天线接口开路**。对应的表现：

| 语句 | 字段 | 值 | 含义 |
|---|---|---|---|
| `GNRMC` | 状态（第 3 个字段）| `V` | 无效定位，经纬度为空 |
| `GNGGA` | 定位质量 / 卫星数 | `0` / `00` | 无定位、0 颗星 |
| `GPGSA` / `BDGSA` | 定位类型 | `1` | 1 = 无定位（2/3 才有）|
| `GPGSV` / `BDGSV` | 可见卫星数 | `0` | 一颗都没看到 |
| `GNZDA` | UTC 时间 | 空 | 时间来自卫星，没星就没时间 |

可能的硬件原因（按概率）：

1. 模块是 **IPEX/u.FL 座**，没插天线（最常见）
2. 有源天线**馈线开路**（`OPEN` 的字面意思）
3. 板载陶瓷天线，但板上**跳线/0Ω 电阻**未焊
4. 天线座虚焊

### 这份数据为什么仍然有价值

室内 + 天线未接 → 拿到的是**全部异常路径的真实样本**：

- 校验和正确但字段全空（最容易让解析器崩溃的输入）
- `RMC` 状态 = `V`（必须判定的分支）
- 卫星数 = 0、无时间戳
- 各种语句长度都有（最短 19 字节，最长 41 字节）

**大多数解析器在"有定位"时能跑，一进无定位就崩。** 这份数据正好用来先测异常路径。

## 四、解析层（纯 C，PC 上可全部验证）

解析分成三个模块，**全部不依赖硬件**，所以能在 PC 上跑完整单测：

| 模块 | 职责 | 为什么拆开 |
|---|---|---|
| `nmea.c` | `$...*CS` 校验和 + 按逗号分段 | 所有语句通用，和业务无关 |
| `rmc.c` | RMC 字段解析：度分→度、节→km/h、`A`/`V` 判定 | 只关心定位 |
| `gps_fix.c` | 定位记录 + 四态子状态机 + 超时 | **时钟由外部注入**，所以超时能测 |

### 关键设计：时钟注入

`GpsFix_Tick(&g, now_ms)` 的 `now_ms` 是参数，不是内部去读 `HAL_GetTick()`。

这样测试里可以直接"把时间拨到 4 秒后"，不用真的等 4 秒：

```c
GpsFix_OnLine(&g, valid_rmc, 1000);   /* 定上位 */
GpsFix_Tick(&g, 2000);                /* 1 秒后：还是 VALID */
GpsFix_Tick(&g, 4001);                /* 3 秒后：变成 STALE */
```

顺带能测**毫秒计数回绕**（`0xFFFFFF00` → `0x00000200` 不能误判成超时）。

### 四种子状态

| 状态 | 含义 | 界面该怎么说 |
|---|---|---|
| `NO_DATA` | 一条合法语句都没有 | 无 GPS 模块 / 接线不对 |
| `FIX_INVALID` | 在收数据，但**本次上电从未定位成功** | 未定位，请到空旷处 |
| `FIX_VALID` | 定位有效且在保鲜期内 | 正常显示位置 |
| `STALE` | **曾经定位成功**，现在过期了 | 定位失效；可把最后坐标灰显 |

**`FIX_INVALID` 和 `STALE` 不能合并** —— 对用户是完全不同的两件事：
一个是"还没找到"，一个是"刚丢了"。丢了才需要提示去检查天线。

### 几个容易做错、这里专门处理了的点

| 坑 | 处理 |
|---|---|
| 状态 `V` 时经纬度是**空串** | 只有当 `valid && has_pos` 才更新坐标。否则会把 0 当成坐标，在地图上画出"几内亚湾"的假点 |
| 度分 `ddmm.mmmm` 不是十进制度 | `deg + mm.mmmm/60`，全程整数（×1e7 定点）|
| 速度单位是**节** | × 1.852 换成 km/h（×1000 定点，`12.345 节 → 22863`）|
| 空字段是合法的 | 分段时**保留空串**，否则字段全部错位 |
| 字段被截断 | RMC 少于 10 段直接判 -1，不硬按下标取值 |
| 校验和错 | 直接丢弃，**不参与任何状态判断** |
| 毫秒回绕 | 一律用 `(uint32_t)(now - then)` 求差 |

## 六点五、这一版做的优化

出去实测（尤其室外长时间跑）之前把几个会**影响结果**的地方改掉了：

### 稳定性

| 优化 | 原来 | 现在 | 为什么 |
|---|---|---|---|
| 环形缓冲 | 1024 | **2048** | 115200 baud 时约 11.5 KB/s，1 KB 只有 **87 ms** 余量；屏幕全屏重绘一次要写 750 KB，可能占用几十毫秒 |
| 丢字节可见 | 内部变量 | **报告里显示** | `rx buffer: DROPPED n bytes`。大于 0 说明主循环被卡住了，而不是"串口有问题" |
| LCD 刷新 | 200 ms | **500 ms** | 每次全屏重绘 750 KB，200 ms 一次是 3.7 MB/s；500 ms 降到 1.5 MB/s |

### 可读性

| 优化 | 说明 |
|---|---|
| 坏校验和**显示百分比** | `3 bad-cs (0.07%)` —— 光看绝对数判断不了是噪声还是故障 |
| 报告**只在变化时打印** | 关键字段（状态/卫星数/坐标/速度/坏校验和/丢字节）变化才打完整报告；没变化每 10 秒打一行心跳。串口不再被重复内容刷屏 |
| 首次定位**原样打印 RMC** | 抓真实样本最方便的方式：不用开 `RAW_ECHO` 刷屏，也不会错过唯一那一条 |

### 工程整洁

| 优化 | 说明 |
|---|---|
