## 1. 屏幕全黑，程序卡在触摸初始化

**现象**

烧进去后屏幕全黑，串口只有一行 `=== F429 tilt ball game ===`，之后不断刷：

```
<<-GTP-ERROR->> I2C Read: 0x814E, 10 bytes failed, errcode: 1! Process reset.
...
LCD ready (cur_lcd=1)
```

注意 `LCD ready` **在报错之后**才出现。

**排查**

1. 看代码顺序：原来是 `GTP_Init_Panel()` 在 `LCD_Init()` **之前**
2. `GTP_Init_Panel()` 内部 `GTP_Read_Version()` 会无限重试
3. 所以 `LCD_Init()` 一直没执行 → 屏幕从没被初始化 → 黑

**根因**

初始化顺序错了。触摸初始化失败时不该阻塞显示。

**解决**

```c
/* 顺序改成：先把屏点亮，触摸做成"可选" */
LCD_Init(); LCD_LayerInit(); LTDC_Cmd(ENABLE); LCD_Clear(BLACK);
printf("LCD ready\r\n");                 /* ← 串口确认 */

touch_ret  = GTP_Init_Panel();
g_touch_ok = (touch_ret < 0) ? 0 : 1;    /* 失败就退回按键 */
```

**教训**

> **外设初始化要按"谁最不该失败"排序。**
> 显示是最必要的，触摸是加分项 —— 就得分清主次，别让加分项阻塞必需品。

## 2. 红灯常亮，`WHO_AM_I` 读回 `0x00`

**现象**

```c
IMU WHO_AM_I failed (got 0x00)
```
红灯常亮（代码里失败就点红灯并卡死）。

**排查与推理**

1. 同一块板、同一颗 MPU6050，在**之前的 HAL 工程里是通的**（`WHO_AM_I = 0x68`）
2. 这次换了工程，我把 MPU6050 接到了野火触摸的软件 I2C 上（`i2c_Start/SendByte/ReadByte`）
3. 查 `bsp_i2c_touch.h` 才发现：

```c
#if 0                                  /* ← 被关掉的分支 */
    GTP_I2C_SCL_PIN  GPIO_Pin_6        /* PB6 */
    GTP_I2C_SDA_PIN  GPIO_Pin_7        /* PB7 */
#else                                  /* ← 实际生效的 */
    GTP_I2C_SCL_PIN  GPIO_Pin_4        /* PH4 */
    GTP_I2C_SDA_PIN  GPIO_Pin_5        /* PH5 */
#endif
```

**触摸的软件 I2C 跑在 PH4/PH5，不是 PB6/PB7。** 所以我的驱动读的一直是 PH4/PH5。

4. 还有一个叠加错误：`MPU_ReadWhoAmI()` 写在 `MPU_Init()` **之前**，那时 PB6/PB7 还是复位默认状态，压根没配成 I2C。

**读回 `0x00` 这个值本身就是线索**：
- 真的没设备 → 上拉会把线拉高，读到 `0xFF`
- 读到 `0x00` → 说明**引脚根本没工作**（不是设备不存在）

**解决**

给 MPU6050 写一套**自己的**软件 I2C，固定在 PB6/PB7：

```c
#define MPU_SCL_PIN  GPIO_Pin_6     /* PB6 */
#define MPU_SDA_PIN  GPIO_Pin_7     /* PB7 */
/* 开漏输出 + 上拉：写 1 释放线，读 IDR 能拿到真实电平，不用切换方向 */
gpio.GPIO_OType = GPIO_OType_OD;
gpio.GPIO_PuPd  = GPIO_PuPd_UP;
```

并把 `MPU_Init()`（含引脚配置）提到读寄存器之前。

**教训**

> **`0x00` 和 `0xFF` 的含义完全不同。**
> `0xFF` = 线是好的、设备没应答；`0x00` = 线被拉死或引脚没配。
> 一个读数就能把排查范围砍一半。

## 3. 文字全挤在左上角一小坨

**现象**

屏幕左上角出现一小块白色噪点，完全不像字。

**排查**

```c
void LCD_DisplayChar(uint16_t Line, uint16_t Column, uint8_t Ascii)
{
  LCD_DrawChar(Line, Column, ...);     /* 直接透传 */
}
void LCD_DrawChar(uint16_t Xpos, uint16_t Ypos, ...)
```

**参数名写着 `Line/Column`（字符格），实际是 `Xpos/Ypos`（像素）。**

我按字符格算：`y/24`、`x/16` → 前几个字全是 `(0,0)`，全叠在一起。

**解决**

```c
/* 之前（错） */
LCD_DisplayChar(y / 24, x / 16, ch);

/* 现在（对）—— 像素值 */
LCD_DisplayChar(y, x, ch);
```

**教训**

> **别信参数名，看它最终传给谁。**
> 一个 `#define` 或一层转发就能让名字和实际语义对不上。

## 4. 文字竖排

**现象**

`LEVEL 1/3` 变成了从上往下排列。

**排查**

修完第 3 条后，我按 `LCD_DisplayChar(x, y, ch)` 传，并让 `x += 16`。
结果字往下走 —— 说明**第 1 个参数控制的是纵向**。

**解决**

```c
LCD_DisplayChar((uint16_t)y, (uint16_t)x, ch);   /* 注意：纵, 横 */
x += FONT_W;
```

**教训**

> 和第 3 条是同一个函数的两层坑：**单位错**（格 vs 像素）+ **顺序错**（横 vs 纵）。
> 遇到"能用但全错位"的库函数，先怀疑这两样。

## 5. 屏幕有扫描条纹

**现象**

画面能显示，但能看到明显的横向扫描条纹，像老电视。

**排查**

算刷新率：

```
PLLSAI: RCC_PLLSAIConfig(420, 7, 6) + RCC_LTDCCLKDivR_Div8
        → 420MHz / 6 / 8 = 8.75 MHz

7 寸屏时序：HTotal = 800+46+1+22 = 869
            VTotal = 480+23+1+22 = 526

刷新率 = 8.75e6 / (869 × 526) = 19 Hz     ← 肉眼看得到闪
```

野火的参数表里 7 寸屏推荐 **21 MHz**（约 46 Hz）。

**解决**

```c
/* 8.75 MHz (19Hz) → 15 MHz (32.8Hz) */
RCC_PLLSAIConfig(420, 7, 7);                   /* R: 6 → 7 */
RCC_LTDCCLKDivConfig(RCC_PLLSAIDivR_Div4);     /* Div8 → Div4 */
```

> 注：中间试过 21MHz（46Hz），但配上 RGB888 会花屏（见第 6 条），
> 最后稳定在 **15MHz + RGB565 = 32.8Hz**。

**教训**

> **"刷新率"要自己算，不能只看例程里的常数。**
> 换屏（分辨率/时序）之后，同一个时钟值对应的刷新率会完全不同。

## 6. 一动球就花屏（最费时的一条）

**现象**

静止画面完全正常（目标区、按钮、球位置都对），
**只要球开始移动，整屏就出现斜向撕裂**。

**排查过程（走了三次弯路）**

| 猜测 | 验证 | 结论 |
|---|---|---|
| ① 相机摩尔纹 | 换角度拍还是一样 | ❌ |
| ② DMA2D 和 LTDC 抢总线 | 画球改用 `LCD_DrawFullRect` | 仍花屏 |
| ③ 局部刷新的擦除逻辑有 bug | 只画不擦 | 仍花屏 |

**转折点**：照片里有一条**从左上贯穿到右下**的亮斜线。
那不是随机噪声 —— 那是**一条"垂直线"被画成了斜线**。

**根因**：查 `LCD_DrawLine` 的垂直分支：

```c
else  /* 垂直线 */
{
    DMA2D_InitStruct.DMA2D_OutputOffset = LCD_PIXEL_WIDTH - 1;   /* 799 */
    DMA2D_InitStruct.DMA2D_NumberOfLine = Length;
    DMA2D_InitStruct.DMA2D_PixelPerLine = 1;
}
```

`DMA2D_OutputOffset` 表示"写完这一行之后，地址要再加多少才到下一行"。
RGB888 每像素 **3 字节**，所以应该是 `800 × 3 = 2400` 字节；
它填的是 **799**。

于是每画一个像素，Y 只前进了 800 像素的 1/3 行 —— **一整条垂直线变成斜线，横扫屏幕**。

而 `LCD_DrawFullCircle` 是由一大堆 `LCD_DrawLine` 拼的 —— 所以**每画一次球，屏幕就被扫一遍**。

**解决（两条一起用）**

1. **球的绘制绕开野火的画线函数**，自己算圆并直接写显存
2. **像素格式从 RGB888 换成 RGB565**

第 2 条同时解决了带宽问题：

| | RGB888 | RGB565 |
|---|---|---|
| 每像素 | 3 字节 | **2 字节**（正好对齐 16 位 SDRAM）|
| 15MHz 下带宽 | 39 MB/s | **25 MB/s** |

**最终稳定组合**

```
RGB565 + 15MHz(32.8Hz) + 自己写显存 + 圆自己算
```

**教训**

> **"一动就坏"和"一直坏"是两类问题。**
> 一直坏 → 配置/初始化错了；一动就坏 → 某个**每次都会被调用**的函数有问题。
>
> 而且**屏幕上出现的规律图形（斜线、条纹、重影）都是线索**，
> 它们直接对应代码里某个算错的方向或偏移 —— 别当成"随机的花屏"。

## 7. 显示不更新，三个按钮叠在一起

**现象**

状态已经是 `RUNNING`（串口日志确认），但屏幕上还显示 `PAUSED`，
而且 `RESUME`、`START`、`RESTART` 三个按钮**叠在同一个位置**。

**排查**

三个按钮叠一起 = **每次重画之前没有真正清屏**。查清屏逻辑没发现问题，
于是怀疑**画到了不同的地方**。

查 `LCD_SetLayer`：

```c
if (Layerx == LCD_BACKGROUND_LAYER)  CurrentFrameBuffer = LCD_FRAME_BUFFER;
else                                 CurrentFrameBuffer = LCD_FRAME_BUFFER + BUFFER_OFFSET;
```

**野火是双图层、两块独立显存。**

我的 `main` 切到了**前景层**，所以野火的文字写在 `基址 + BUFFER_OFFSET`；
而我"直接写显存"写的是**基址** —— **画到另一块内存里去了**。

所以：
- 我的矩形 → 背景层
- 文字 → 前景层（盖住背景层）
- 我的清屏 → 只清了背景层，前景层的字永远留着

**解决**

```c
#define FB_BASE  ((volatile uint8_t *)(LCD_FRAME_BUFFER + BUFFER_OFFSET))
```

**教训**

> 自己直接操作显存之前，**先确认"当前生效的显存基址是哪个"**。
> 带图层/LTDC 的板子经常有两块甚至三块显存，`LCD_FRAME_BUFFER` 未必是正在显示的那块。

## 8. 串口被 GTP 报错刷爆（野火库）

**现象**

即使把触摸初始化代码用 `#if 0` 关掉了，串口**仍然**每秒刷几十行：

```
<<-GTP-ERROR->> I2C Read: 0x814E, 10 bytes failed, errcode: 1! Process reset.
```

**排查**

关掉 `main` 里的初始化没用 → 说明调用点不在 `main`。
全局搜 `GTP_TouchProcess` → 发现它在**中断里**：

```c
void SysTick_Handler(void)
{
    static uint8_t timecount = 0;
    if (timecount >= 10)
    {
        timecount = 0;
        GTP_TouchProcess();      /* ← 每 10ms 调一次 */
    }
    TimingDelay_Decrement();
    timecount++;
}
```

**根因**

野火把触摸轮询塞进了 SysTick 中断。触摸不通时它会一直重试并打印。

**解决**

注释掉那一行（改用主循环统一轮询 `GTP_Execu()`，避免双份轮询）。

**教训**

> **中断里不该做重活，更不该做"会失败并重试"的活。**
> 这类代码平时看不出问题，一旦外设不通就会把整个系统拖垮。
>
> 排查"我明明注释掉了还在跑"这类现象时，**第一反应是去中断里找**。

## 9. `cur_lcd` 默认 5 寸 → 7 寸黑屏（野火库）

**现象**

改完第 1 条后屏还是黑的，串口正常。

**排查**

野火这套工程是"4.3/5/7 寸兼容"的，靠一个全局变量选时序表：

```c
LCD_TypeDef cur_lcd = INCH_5;      /* ← 默认 5 寸 */
```

| 参数 | 5 寸 | 7 寸 |
|---|---|---|
| VSW | 3 | **1** |
| HFP | 40 | **22** |
| VFP | 13 | **22** |

**根因**

用 5 寸的时序驱动 7 寸屏 → LTDC 的行场信号对不上 → 黑屏。

**解决**

```c
LCD_TypeDef cur_lcd = INCH_7;
```

**教训**

> **"通用工程"的默认值一定是最常见的那种配置，不一定是你的。**
> 拿到一份能跑别人板子的工程，第一件事是**逐个核对默认参数**：
> 屏幕型号、晶振频率、时钟树。

## 10. `LCD_DrawLine` 的垂直偏移（野火库）

已在**第 6 条**里详细记录。单独列出来是因为它足够隐蔽：

- 它是一个**库函数的内部 bug**
- 只在"画垂直线"这个分支出现
- 表现是**整屏斜纹**，很容易被误判成"花屏 / 带宽 / 时序"

**规避手段**：不用它的 `LCD_DrawLine` / `LCD_DrawFullCircle`，
自己算圆、自己写显存。

## 11. 触摸一直 `Unknown IC Version`（野火库默认值）

**现象**

```c
LCD ready (cur_lcd=1)
<<-GTP-ERROR->> I2C Read: 0x8047, 1 bytes failed, errcode: 1! Process reset.
<<-GTP-ERROR->> I2C Read: 0x8140, 6 bytes failed, errcode: 1! Process reset.
<<-GTP-INFO->> Unknown IC Version:
```

**排查**

代码没错、引脚没错 —— 是**找错了设备地址**。看 `bsp_i2c_touch.h`：

```c
/* 如果用的是 4.3寸/5寸 的 RGB 屏，其触摸芯片可能是 GT1151QM */
#define LCD_TOUCH_IC_GT1151QM           /* ← 它被定义了 */

#ifndef LCD_TOUCH_IC_GT1151QM
#define GTP_ADDRESS   0xBA              /* GT911，   7 位 0x5D */
#else
#define GTP_ADDRESS   0x28              /* GT1151QM，7 位 0x14 */
#endif
```

**根因**

这个宏是给 **4.3/5 寸**屏准备的（头文件注释写得很清楚）。
**7 寸屏的触摸芯片是 GT911，地址 `0xBA`**。
按 `0x28` 去读当然没人应答。

**解决**

注释掉 `#define LCD_TOUCH_IC_GT1151QM`。

**教训**

> **同一个系列的不同尺寸屏幕，触摸 IC 可能完全不同。**
> 头文件里那些"如果是 4.3/5 寸就改这里"的注释，**一定要读**，
> 而且读完要确认自己**没有**定义它。

# 总结：这 11 条能提炼出什么

| 类型 | 教训 |
|---|---|
| **顺序** | 初始化要按"谁最不该失败"排序；先配引脚再读寄存器 |
| **读数的含义** | `0x00` ≠ `0xFF`，一个读数能把排查范围砍一半 |
| **别信参数名** | 单位（格/像素）、顺序（横/纵）都要看它最终传给谁 |
| **"一动就坏"** | 去找那个**每次都会被调用**的函数 |
| **规律图形是线索** | 斜线 = 偏移算错；叠字 = 没清屏；条纹 = 刷新率 |
| **中断** | 中断里只做"记一笔"，不做重活、不做会重试的事 |
| **通用工程** | 默认值一定不是你的，逐个核对 |
| **显存** | 操作显存前先确认"当前生效的基址是哪块" |
