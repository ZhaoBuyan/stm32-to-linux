# 关于文件编码（打开源码看到乱码时看这里）

## 结论先说

**文件没有坏，是编辑器用错了编码打开。**

野火的这套源码是 **GBK 编码**（2015 年前后的国内代码基本都是）。
而 VS Code / 记事本默认按 **UTF-8** 打开，中文注释就会变成 `���ĵ�ʹ��` 这样的方块。

> 验证方法：把文件按 GBK 解码，内容立刻正常。
> 本文档所在工程的 26 个 GBK 文件逐字节与野火原件一致，没有一个是损坏的。

---

## 哪些是 GBK，哪些是 UTF-8

| 类型 | 编码 | 举例 |
|---|---|---|
| **野火自带的源码** | **GBK** | `User/lcd/bsp_lcd.c`、`User/touch/gt9xx.c`、`User/sdram/bsp_sdram.c` … |
| ST 官方驱动 | Latin-1 / 其他 | `stm32f4xx_qspi.c`（只有 © 之类的字符，不用管） |
| 说明文档 | **已转 UTF-8** | `必读说明.txt`、`Libraries/CMSIS/说明.txt` |
| **我们自己写的代码** | **UTF-8** | `User/game/*.c/h`、`User/imu/*.c/h`、`User/main.c` |

## 为什么不把源码也转成 UTF-8

因为 **Keil 默认按 GBK 显示源文件**。转成 UTF-8 之后：

- VS Code 里正常了
- **Keil 里反而全变乱码**

所以源码保持 GBK（跟 Keil 一致），文档转 UTF-8（不进编译器，随便看）。

---

## 在 VS Code 里怎么正常看野火的源码

**方法一（临时，推荐）**

1. 打开那个 `.c` 文件
2. 看右下角状态栏，点编码（显示 `UTF-8`）
3. 选 **`Reopen with Encoding`** → **`GB18030`**（GBK 的超集）

**方法二（自动识别，省事）**

在 VS Code 设置里打开：

```json
"files.autoGuessEncoding": true
```

之后打开 GBK 文件会自动识别，不用手动切。

> 注意：**改了编码只是显示方式，别修改后保存成别的编码**，否则源码里的中文注释会真的被改坏。

---

## 在 Keil 里

Keil 默认就是 GBK（跟随中文 Windows 的代码页），打开野火的源码**本来是正常的**。

但如果看到乱码，检查：

```
Edit → Configuration → Editor → Encoding
```

选 **Chinese GB2312**（或 Default，跟随系统）。

---

## 一句话总结

> **源码 = GBK（配合 Keil），文档 = UTF-8（方便阅读）。**
> 看到乱码先怀疑"用错编码打开"，不要怀疑文件坏了 —— 这次就是。
