# 状态词典与不变量

> T01 交付物之一。**状态 = 系统"待在里面"的一种情况**，能持续，直到被事件推走。
> **不变量 = 只要处于这个状态，就必须一直成立的事。**
> 不变量在三个地方各管一件事：需求上防漏、代码里变成进入/退出动作、测试里变成断言。

## 一、状态清单（6 个）

| # | 状态 | 名称 | 含义 |
| --- | --- | --- | --- |
| 1 | `DEV_INIT` | 自检 | 上电后初始化关键外设并检查是否正常 |
| 2 | `DEV_IDLE` | 空闲 | 自检通过，等待用户下达准备命令 |
| 3 | `DEV_READY` | 已准备 | 准备动作（上料、设参数、预热）已完成，等待启动 |
| 4 | `DEV_RUNNING` | 运行中 | 正在执行动作，运行计时在走 |
| 5 | `DEV_PAUSED` | 暂停 | 动作中断但现场保留，计时暂停 |
| 6 | `DEV_ERROR` | 故障 | 已锁存故障，安全停机，等待人工排除并复位 |

## 二、不变量

| 状态 | 不变量 | 为什么要这条 |
| --- | --- | --- |
| `INIT` | 执行机构断电；外部命令一律不生效 | 初始化未完成时 GPIO 可能还是复位默认值，此时响应命令等于输出未知电平 |
| `IDLE` | 执行机构断电；**收到 START 必须忽略** | 未准备就启动 = 带着未定义状态运行。这也是验收用例 M01 的要求 |
| `READY` | 料已就位、参数已设；执行机构**仍断电** | 准备完成 ≠ 开始运行。断电状态保证"准备好了但没动"是安全的 |
| `RUNNING` | 执行机构**通电且推进**；运行计时在走 | 唯一允许做功的两个状态之一 |
| `PAUSED` | 执行机构**保持通电但不推进**；计时暂停 | 保留现场：继续时不必重新上电、不必重新准备 |
| `ERROR` | 执行机构**必须断电**；故障未清时 `RESET` 被拒绝 | 出事时保留能量是危险的（堵转发热、继电器卡死）。M03 要求故障仍在时 RESET 无效 |

## 三、由不变量推出的安全规律

把"执行机构"这一列单独拉出来：

| 状态 | 执行机构 |
| --- | --- |
| INIT | 断电 |
| IDLE | 断电 |
| READY | 断电 |
| RUNNING | 通电且推进 |
| PAUSED | 通电但不推进 |
| ERROR | 断电 |

规律：**只有 RUNNING 和 PAUSED 允许通电；其余状态一律断电。**

这条规律叫 **失效安全（fail-safe）**：系统默认是"关"的，必须主动进入 RUNNING 才会做功。
这样掉电、复位、程序跑飞，结果都落在"关"这一侧。

如果反过来设计（默认通电、出事才关），程序跑飞时输出会保持在上一次的值，
在真实设备上可能直接造成事故。

## 四、状态与"状态标志位"的边界

项目里同时存在"状态"和"状态标志位"，两者不是一回事：

| | 状态（`DeviceState`） | 标志位（如 `fault_active`） |
| --- | --- | --- |
| 数量 | 同一时刻**只能有一个** | 可以同时有多个 |
| 作用 | 决定"现在在做什么" | 记录"某个条件是否成立" |
| 例子 | `DEV_RUNNING` | `fault_active == true` |

两者配合的方式是**守卫条件**：状态机在某个转换上读标志位，决定放不放行。
例如 `ERROR --[RESET 且 fault_active == false]--> IDLE`：

- `fault_active` 是标志位，由 `DeviceFsm_SetFault()` 修改
- 只有它被清除后，`RESET` 这个事件才会被接受

**不能把"故障"做成一个标志位就当作状态用**，也不能把"暂停"做成标志位 ——
因为暂停期间允许的事件集合（只有 RESUME 和 STOP）和运行期间完全不同，
这必须由状态来区分。

## 五、状态转移的骨架（详见《转换表》）

```
INIT ──[BOOT_OK]──▶ IDLE ──[PREPARE]──▶ READY ──[START]──▶ RUNNING
                      ▲                   │                  │  ▲
                      │                   │STOP              │  │RESUME
                      │                   ▼                  ▼  │
                      │                 IDLE                PAUSED
                      │                   ▲                  │
                      │                   └──────[STOP]──────┘
                      │
                      └──────────[RESET 且 !fault_active]── ERROR ◀──[FAULT] 任意状态
```
