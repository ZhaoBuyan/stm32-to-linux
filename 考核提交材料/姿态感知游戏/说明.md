# 简要说明

工程：STM32F429 姿态感知交互游戏（裸机，7 寸 RGB 电容屏）

用板载 MPU6050 感知倾斜，控制屏幕上的小球滚到目标区；绕过墙体、避开危险区。
共 12 关，可按按键或点屏幕操作。

## 三、操作方法

**上电后**：屏幕显示关卡与 `START` 按钮，白灯。**立刻把板子放平别动**（约 1 秒静止校准）。

| 操作 | 方式 |
| --- | --- |
| 开始游戏 | 点 `START` 或按 KEY1 |
| 控制小球 | 倾斜开发板（前后左右）|
| 暂停 | 点状态栏里的 `PAUSE` 或按 KEY1 |
| 继续 | 点 `RESUME` 或按 KEY1 |
| 重玩本关 | 点 `RESTART` 或按 KEY2 |
| 下一关 | 球进绿色目标区后点 `NEXT` 或按 KEY1 |
| 失败重试 | 碰红色危险区后点 `RETRY` 或按 KEY1 |

**串口** 115200-8-N-1，会打印校准结果和状态切换日志。

## 四、显示参数是怎么定的（可被追问）

| 方案 | 带宽 | 刷新率 | 结果 |
| --- | --- | --- | --- |
| RGB888 + 8.75 MHz | 22 MB/s | 19 Hz | 干净但**肉眼可见闪烁** |
| RGB888 + 21 MHz | 53 MB/s | 46 Hz | 不闪但**一动就花屏** |
| **RGB565 + 15 MHz** | **25 MB/s** | **32.8 Hz** | **既清楚又不花屏（最终采用）** |

关键原因：**SDRAM 是 16 位宽**，RGB888 每像素 3 字节对不齐总线，
每个像素都要"读-改-写"；RGB565 的 2 字节正好一次传输。

## 五、存在的问题

1. **刷新率只有 32.8 Hz**，快速移动时可能有轻微撕裂。
   原因：受 SDRAM 带宽限制，再往上提就会花屏（见上表）。
   更好的做法：改用双缓冲 + LTDC 垂直消隐同步，但需额外 768 KB 显存。

2. **野火库里有两个 bug，本项目是绕过去的，没有修库**。
   一是 `LCD_DrawLine` 垂直分支的 `DMA2D_OutputOffset` 把像素当字节（所以不用它的画线/画圆）；
   二是 `SysTick_Handler` 里跑触摸轮询，触摸不通时会把串口刷爆（已注释）。
   更好的做法：直接改库并在 README 里记录，但会影响野火其他例程。

3. **触摸坐标没做四角校准**，直接用 GT911 上报的原始坐标。
   实测和按钮对得上，但如果换屏或排线，可能需要交换 X/Y 或做线性拟合。

4. **关卡数据是手写的坐标表**，没有可视化编辑器，改关卡要手算。
   已在 PC 端用网格 BFS 验证每关都存在通路，避免出现走不通的关卡。
