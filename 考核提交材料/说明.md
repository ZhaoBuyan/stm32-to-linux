## 三、操作方法

串口 115200、8 位数据位、无校验、1 位停止位。使用串口调试助手的「文本发送 + 追加换行」。

| 操作 | 发送 | 响应 |
| --- | --- | --- |
| 开灯 | `@LED=1` | `OK,LED=1` |
| 关灯 | `@LED=0` | `OK,LED=0` |
| 灯状态查询 | `@LED?` | `LED=1` |
| 环境查询 | `@ENV?` | `ENV,T=26,H=58` |
| 启动闪烁 | `@BLINK=1` | `OK,BLINK=1` |
| 停止闪烁（并关灯） | `@BLINK=0` | `OK,BLINK=0` |
| 开启周期上报 | `@REPORT=1` | `OK,REPORT=1` |
| 关闭周期上报 | `@REPORT=0` | `OK,REPORT=0` |

**按键**：KEY1 开灯、KEY2 关灯。按键操作会退出闪烁。

**接收超时演示**：关闭「追加换行」，发送 `@LED=`，等待 2 秒 → 返回一次 `ERR,TIMEOUT`。

## 四、存在的问题

1. **超时 / 闪烁 / 上报按 `Cmd_Tick10ms()` 的调用次数计时**，而不是用 tick 差值。DHT11 读取会阻塞约 20 ms 并吃掉几个 tick，误差约 1%。
   更好的做法：收到 `@` 时记录当刻的 `g_tick10`，之后用 `g_tick10 - start >= 200` 判断（无符号相减自动回绕，tick 溢出也正确）。

2. **串口接收缓冲区由中断和主循环共用**。极端情况（10 ms 内连发两条命令）可能丢掉一条响应。
   更好的做法：中断只把字节放进环形缓冲，接收状态机整体放在主循环。
